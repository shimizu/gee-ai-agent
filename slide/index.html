gee-ai-agent デモ

話しかけるだけで、AI が衛星データ（Google Earth Engine）を調べて地図に出す

「先月のアマゾンの降水を平年と比べて」と話す → Gemini が聞き返す → Claude が GEE を実行 → 地図に出て結果を読み上げる。

アーキテクチャ概要

音声
→
Gemini Live会話して指示文を作る
→
run_prompt
(function call)
→
ClaudeEE を実行
→
地図に表示
結果を読み上げ
  • Gemini は会話担当、分析は Claude 担当
  • Gemini に渡す関数は 2 つだけ：
    run_prompt（Claude に指示を送る）／capture_map（地図を見る）
  • Claude の完了を Gemini に通知 → 結果を読み上げ
  • バックエンドなし。すべてブラウザから直接 API を呼ぶ
Gemini にはアプリのツール（GEE・地図など 20 個以上）を渡さない。音声の相棒に徹させる。

構成図

上段が外部 API、下の点線枠がブラウザ。Gemini は run_prompt で Claude に依頼し、完了通知を受けて読み上げる。すべてブラウザから直接つながる。

01

Gemini Live API について

Gemini Live API とは

The Live API enables low-latency, real-time voice and vision interactions with Gemini.
WebSocket（WSS）
ステートフルな接続で音声・画像・テキストをストリーミング
音声 in / out
入力 PCM16 16kHz・出力 PCM16 24kHz
割り込み（barge-in）
話している途中でユーザーが遮れる
書き起こし
入力・出力の両方をテキストで受け取れる
Function calling
アプリの関数を呼ばせられる
Google 検索
グラウンディングを併用できる

出典: aistudio.google.com/docs/live-api（Preview）

普通の Gemini API はリクエスト/レスポンス。Live は WebSocket を張りっぱなしで、マイク音声を流し続け、音声が返ってくる。

Gemini Live API の使い方


import { GoogleGenAI, Modality } from '@google/genai'

const ai = new GoogleGenAI({ apiKey })
const session = await ai.live.connect({
  model: 'gemini-3.8-live',
  config: {
    responseModalities: [Modality.AUDIO],
    systemInstruction,                 // 役割・話し方
    outputAudioTranscription: {},      // 字幕用
  },
  callbacks: {
    onmessage: (msg) => {
      for (const p of msg.serverContent?.modelTurn?.parts ?? [])
        if (p.inlineData) player.enqueue(p.inlineData.data) // 24kHz PCM
      if (msg.serverContent?.interrupted) player.flush()     // 割り込み
    },
  },
})

// マイク（AudioWorklet → PCM16 → base64）を流し続ける
session.sendRealtimeInput({ audio: { data: base64, mimeType: 'audio/pcm;rate=16000' } })

ブラウザでの注意: AudioWorklet は同一オリジンのファイルで読み込む（blob: は CSP で弾かれる）／CSP の connect-src に wss:// を足す

SDK の live.connect だけで WebSocket を意識しなくて済む。大変なのは音声まわり（16kHz で録って PCM16 にする、24kHz を途切れなく再生する、割り込まれたら捨てる）。

Gemini Live API に tool を登録する方法

① config.tools に関数宣言を渡す


tools: [{
  functionDeclarations: [{
    name: 'run_prompt',
    description: 'Claude への指示文を送信して実行する',
    parameters: {
      type: 'OBJECT',
      properties: { text: { type: 'STRING' } },
      required: ['text'],
    },
  }],
}],

② toolCall を受けて結果を返す


onmessage: async (msg) => {
  if (!msg.toolCall) return
  const functionResponses = []
  for (const c of msg.toolCall.functionCalls) {
    const response = await handlers[c.name](c.args)
    functionResponses.push({
      id: c.id, name: c.name, response,
    })
  }
  session.sendToolResponse({ functionResponses })
}
  • 渡すのは UI 操作の 2 関数だけ（run_prompt / capture_map）。分析ツールは Claude 側に置く
  • capture_map は 画像を先に送ってから ツール応答を返す（逆だと画像を見ずに話し始める）
  • 関数呼び出しは既定で同期（応答が返るまで待つ）。モデルによっては NON_BLOCKING も選べる
ツール定義は普通の function calling と同じ形。違いは結果を sendToolResponse で WebSocket に返すところ。

tool はどうやって実行される？

Gemini は関数を実行しない。「この関数をこの引数で呼んで」というメッセージを送ってくるだけ

ユーザーが話す
「この辺の植生を調べて」
→
Gemini関数を使うと判断
引数（指示文）を作る
→
toolCall
実行の依頼
→
ブラウザ関数を実行
→
toolResponse
結果を返す
モデル（Gemini）の担当
  • 使うかどうかの判断と、引数づくり
  • 宣言された関数しか呼べない
アプリ（ブラウザ）の担当
  • 実際の処理（何をするかはコード次第）
  • 結果を id 付きで返す

Claude の tool use や OpenAI の function calling と同じ考え方。違うのは、音声の WebSocket の中で起きること

モデルが勝手にブラウザを操作するわけではない。args.text もユーザーの発話そのままではなく、会話から Gemini が組み立てた Claude 向けの指示文。結果を返さないと同期の場合は待ち続けるので、エラーでも必ず返す（このアプリは { ok:false, error } で返す）。

toolCall はどうやって届く？

WebSocket 1 本で、JSON のメッセージを両方向に流し続けている。toolCall もその 1 つ

ブラウザ → Gemini（送る）
  • マイク音声のかけら（約 8ms ごと）
  • 画像（地図のスクショ）
  • ツールの結果（toolResponse）
Gemini → ブラウザ（届くたびに onmessage）
  • 声のかけら・字幕のかけら
  • 言い終わり（turnComplete）
  • 関数の依頼（toolCall）

// 「こんにちは」（約 1 秒）＝ 音声メッセージを 100 回以上送る。中身は文字ではなく波形
{ realtimeInput: { audio: { data: "AAEC/f8…", mimeType: "audio/pcm;rate=16000" } } }

// 届く toolCall も、メッセージの 1 種類にすぎない
{ toolCall: { functionCalls: [{ id: "abc123", name: "run_prompt", args: { text: "…" } }] } }
ユーザーの声は onmessage を呼ばない（こちらが送る側）。AudioWorklet の process() 1 回 = 128 サンプル = 16kHz で約 8ms 分を 1 メッセージとして送っている。Gemini からの応答も細切れで、1 つ届くたびに onmessage が呼ばれ、中身を見て再生・字幕・関数実行に振り分ける。

toolCall はいつ届く？

onmessage は、喋っているかどうかに関係なくメッセージが届くたびに呼ばれる

ユーザーの発話中届くのは書き起こしなど。toolCall は基本来ない
話し終わった直後Gemini が判断して、音声で答えるか toolCall を送る
Gemini の再生中「調べますね」と言いながら toolCall が届くこともある

音声チャンクは届いた順に先に再生予約されるので、再生は受信より遅れる。そのため再生中に toolCall が届くことがある

「話している最中は来ない」はドキュメントの説明（話し終わりを検出してから応答を作る）からの推測で、実機検証はしていない。

組み込みツール：Google 検索

Live API で使える組み込みツールは、今のところ Google 検索だけ

Google 検索対応
Google マップ非対応
コード実行非対応
URL コンテキスト非対応

自作の関数と並べて渡すだけ


tools: [
  { googleSearch: {} },             // 組み込み
  { functionDeclarations: [...] },  // 自作
],
gee-ai-agent での使い方
  • 最近の災害の日付や地名を確かめてから、Claude への指示文を作る
  • 数値の根拠には使わない
  • 設定で ON / OFF（既定は OFF）

出典: aistudio.google.com/docs/live-api/tools（gemini-3.8-live など 4 モデルとも同じ対応状況。Preview のため変わる可能性あり）

ドキュメントの説明は「精度を上げてハルシネーションを防ぐ」。自作の関数と違い、検索の実行はアプリ側で書かなくてよい（公式サンプルは toolCall の処理なしで動いている）。Google マップ・コード実行・URL コンテキストは通常の Gemini API にはあるが、Live API では全モデル非対応。検索は別課金（設定画面でも注意書き）。

02

音声 UI の可能性

大量のボタンやスイッチに埋もれることがない

従来の GIS / 分析 UI
  • データセット・期間・領域・バンド・カラーマップ…
  • 機能を足すほどボタンと設定が増える
  • どこに何があるかを覚える必要がある
音声 UI
  • 「先月のアマゾンの雨、平年と比べて」
  • 機能が増えても入口は 1 つ
  • 画面は結果を見る場所になる

このアプリはスマートフォンでも動作するので、寝ながらでも衛星データの分析が出来ます

gee-ai-agent のツールは 20 個以上あるが、ユーザーが触るのはマイクボタン 1 つ。スマホでも動くので、布団の中から話しかけるだけで分析できる。

UI がサポートも兼ねる

聞き返す依頼が曖昧なら「場所・期間・知りたいこと」がそろうまで質問する
噛み砕くNDVI などの専門用語を、相手に合わせて言い換える
見る「この辺」と言われたら地図のスクショを撮って確認する（capture_map）
伝えるClaude の分析が終わったら、結果を 1〜2 文で読み上げる

これらは全部 system instruction に書いているだけ。ヘルプページもチュートリアルも作っていない

操作 UI とヘルプ・サポート窓口が同じものになる。プロンプトを書き換えるだけで振る舞いを変えられる。

Gemini Live API は良いぞ

SDK で数十行live.connect と sendRealtimeInput で音声 UI が動く
function calling で既存アプリにつなげるUI 操作の関数を渡すだけ
UI とサポートを兼ねるボタンを増やさずに機能を増やせる
音声 UI はチャット UI の次の入口になる。自分のアプリにもぜひ。
